# QuickCue — быстрый AI-помощник для iPhone

SwiftUI MVP для **iPhone 15 Pro Max** с минимальной версией **iOS 26.0**. Приложение работает только пока открыто: потоково распознаёт русскую речь, локально замечает вопросы, показывает короткий ответ тезисами, фотографирует программные задачи и хранит историю на устройстве.

Проект стартует в **Mock-режиме** и не требует реальных API-ключей. Подключаемые клиенты для OpenAI, DeepSeek, Anthropic Claude, xAI Grok и YandexGPT подготовлены, но сеть включается только после явного отключения Mock и сохранения ключа в Keychain.

## Что работает в версии 0.3

- SwiftUI-интерфейс из пяти вкладок: эфир, диалог, камера, история, настройки.
- Явный запуск/остановка микрофона, `ru_RU`, partial speech results.
- Финализация фразы после паузы 650 мс и локальный `QuestionDetector`.
- Ручной ввод вопроса для быстрой проверки без речи.
- Большая быстрая камера на вкладке «Эфир»: одно нажатие сразу делает снимок, запускает OCR и отправляет задачу.
- Режим «Диалог» с пузырями «Вы», «Собеседник» и «QuickCue», потоковыми AI-подсказками и тремя крупными кнопками: фото, микрофон, завершить.
- Роль говорящего в «Диалоге» предположительно определяется по смыслу фразы и исправляется круглой стрелкой рядом с пузырём: вправо — перенести в «Вы», влево — в «Собеседник». Архитектура `SpeakerAttributing` готова для подключения настоящей диаризации.
- Потоковая карточка ответа со статусами «в очереди / думаю / пишу / готово / ошибка», повтором, вариантами «Короче/Подробнее» и оценкой ответа.
- Защита от одинакового вопроса в течение 8 секунд, не более двух AI-запросов одновременно и очередь вместо потери третьего вопроса.
- SwiftData для сессий, расшифровок, ответов, фото и usage.
- Камера, Vision OCR для русского/английского текста, локальное сохранение JPEG; в отдельном режиме снимок можно проверить, переснять и исправить OCR-текст.
- Keychain для секретов; ключи не лежат в исходниках, plist или xcconfig.
- API-ключ можно ввести вручную, сфотографировать или выбрать его снимок. Apple Vision распознаёт строку локально, показывает только маскированную проверку, а фото ключа не сохраняется.
- Понятная проверка API-подключения с тестовым запросом и измерением задержки; модели и тарифы убраны в расширенные настройки.
- Неограниченный список пользовательских OpenAI-совместимых провайдеров: отдельные имя, HTTPS Base URL, авторизация, ID модели, тарифы и ключ Keychain. Любой из них выбирается основным или резервным.
- Встроенный редактор системного промпта с тремя готовыми вариантами и возможностью полностью изменить инструкцию.
- Latency fallback: резервный запрос стартует после настраиваемой задержки, выигрывает первый текстовый поток.
- Мягкие лимиты: 150 вопросов и 30 фотографий за сессию, контекст 5 минут, месячный бюджет 2 000 ₽.
- Учёт input/output tokens и оценка стоимости по актуальным тарифам, которые владелец вводит для каждого провайдера.
- Ручные экранные кнопки камеры и слой `CaptureTriggering` для кастомной BLE-кнопки.
- История сгруппирована по сессиям и датам, поддерживает фильтры «Все/Речь/Фото», миниатюры и экспорт текста сессии.
- Экран не гаснет во время активного прослушивания; при смене вкладки микрофон останавливается.
- Unit tests для детектора, определения роли, mock stream, SSE parser, registry и стоимости запускаются в GitHub Actions.
- Светлый минималистичный 1024×1024 App Icon без текста в общей фиолетовой палитре приложения.

## Что намеренно не заявлено как готовое

- Проект создан на Windows, где нет Xcode/iOS SDK. Структура и исходники проверяются статически, но финальную компиляцию, подпись, permissions и TestFlight нужно подтвердить на macOS.
- Обычный Bluetooth selfie remote обычно эмулирует volume key. Надёжного публичного API для превращения такого нажатия в команду приложения нет. В MVP нет MPVolumeView/KVO-хаков; поддерживается честная BLE-точка расширения с известными service/characteristic UUID.
- Модели и тарифы быстро меняются. ID моделей редактируются на устройстве, денежные тарифы по умолчанию равны нулю и должны быть сверены перед live-тестом.
- Apple Speech может обращаться к сети. Приложение не хранит аудио, но не обещает полностью offline speech recognition.
- Системный speech-to-text не предоставляет приложению надёжную личность говорящего. В 0.3 роли в «Диалоге» — прозрачное смысловое предположение, а не биометрическое распознавание голоса. Для настоящей диаризации нужен отдельный локальный ML-модуль или облачный сервис.
- Прямые ключи в Keychain подходят только для личной сборки. Перед распространением другим пользователям клиенты следует направить на собственный backend, где лежат provider keys, rate limits и billing rules.
- Для YandexGPT фото проходит через локальный OCR. Прямой vision-запрос в текущем адаптере не включён.

## Быстрый запуск на macOS

Требуются Xcode 26 или новее с iOS 26 SDK, macOS, Apple Developer account и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
brew install xcodegen
cd /path/to/QuickCue-iOS
xcodegen generate
open QuickCue.xcodeproj
```

В Xcode:

1. Выберите target `QuickCue` → Signing & Capabilities → свою Team.
2. Если Bundle ID занят, измените `PRODUCT_BUNDLE_IDENTIFIER` в `Config/Shared.xcconfig`.
3. Выберите iPhone 15 Pro Max с iOS 26 как устройство запуска.
4. Запустите приложение. Тестовый режим включён автоматически.
5. Разрешите микрофон/Speech для вкладки «Эфир» и камеру для вкладки «Камера».
6. Нажмите «Начать слушать» или введите вопрос вручную. Ответ должен прийти частями примерно за 0,2–0,5 с в Mock.

`QuickCue.xcodeproj` намеренно игнорируется: источник истины — `project.yml`, чтобы настройки проекта были обозримы и воспроизводимы.

## Подключение встроенного провайдера

1. В «Настройки → Подключение AI» откройте нужного провайдера.
2. Проверьте актуальный ID модели и при необходимости измените его.
3. Введите текущую цену в рублях за 1 млн input/output tokens, если нужна денежная оценка.
4. Откройте «API-ключ» и введите его либо распознайте с фотографии. Проверьте похожие символы `0/O`, `1/l/I`; сохранённое значение никогда не показывается обратно.
5. Для YandexGPT дополнительно заполните Yandex Cloud Folder ID.
6. Нажмите «Проверить подключение», выберите основной и резервный AI, затем выключите тестовый режим.

### YandexGPT 5 Pro

Стартовый ID модели в QuickCue — `yandexgpt-5-pro/latest`, запрос отправляется на официальный OpenAI-совместимый endpoint Yandex AI Studio. Для работы нужны одновременно:

1. Привязанный к облаку платёжный аккаунт. На присланном скриншоте Yandex явно показывает, что он ещё не привязан.
2. Сервисный аккаунт с ролью `ai.languageModels.user` в нужном каталоге.
3. Folder ID этого каталога в поле QuickCue.
4. Свежий API-ключ сервисного аккаунта с правом выполнять запросы к Foundation Models.

Ключ на скриншоте нельзя считать приватным, даже если часть строки закрашена. Перед первым подключением удалите его в Yandex Cloud и выпустите новый; новый ключ вводите только на iPhone.

## Как добавить любой свой API-провайдер

QuickCue не ограничен одним полем «Свой API». Нажмите «Настройки → Подключение AI → Добавить своего провайдера» и создайте отдельную карточку для каждого сервиса. Введите:

1. Понятное название — например, `Рабочий шлюз` или `CheapVibeCode`.
2. HTTPS Base URL. Для адреса без пути QuickCue добавит `/v1/chat/completions`; полный endpoint тоже допускается.
3. Тип авторизации `Bearer` или `Api-Key`.
4. Точный ID модели из личного кабинета сервиса.
5. Необязательные тарифы для локальной оценки расходов.
6. Отдельный API-ключ — вручную или по фотографии.

После сохранения нажмите «Сохранить и проверить». Успех и время до первого текста появятся прямо в карточке. Затем этот сервис можно выбрать основным либо резервным в верхнем разделе настроек. Удаление одной карточки не затрагивает ключи и настройки других провайдеров.

Сейчас пользовательские карточки поддерживают распространённый протокол OpenAI Chat Completions со streaming. Это подходит большинству агрегаторов моделей, которые заявляют OpenAI compatibility. Если сервис использует собственный формат API, понадобится отдельный адаптер в коде.

### CheapVibeCode из присланного скриншота

В карточке есть кнопка «Заполнить для CheapVibeCode»: она подставляет `https://ru.cheapvibecode.ru` и Bearer-авторизацию. ID модели всё равно нужно скопировать из раздела моделей этого сервиса — QuickCue не угадывает его по маркетинговому названию.

Плюс агрегатора — один баланс и один ключ для разных моделей. Минусы — ещё один посредник видит запросы, может вести собственные логи, менять маршрутизацию и добавляет отдельную точку отказа. Поэтому QuickCue показывает предупреждение о приватности и не считает пользовательский шлюз автоматически доверенным. Ключ, попавший на скриншот, также лучше отозвать и создать заново.

## Быстрые и контролируемые фотографии

- Кнопка камеры на «Эфире» и левая кнопка в «Диалоге» работают в один тап: QuickCue сам открывает камеру, фотографирует, распознаёт текст и отправляет задачу.
- Отдельная вкладка «Камера» предназначена для сложного кадра: после снимка показываются фотография и редактируемый OCR-текст, затем владелец выбирает «Переснять» или «Отправить».
- Быстрый сценарий оптимизирован для скорости, отдельная вкладка — для точности и контроля расходов.

## Как работает вкладка «Диалог»

1. Центральная кнопка запускает непрерывное распознавание речи.
2. Вопросительные и повелительные фразы предварительно относятся к собеседнику; остальные — к владельцу iPhone.
3. Метка «Вы/Собеседник» показывает текущую роль. Круглая стрелка рядом с пузырём переносит фразу на другую сторону чата и меняет автора одним нажатием.
4. На вопрос собеседника создаётся потоковая реплика QuickCue. Для любой другой реплики доступно действие «Спросить AI».
5. Левая кнопка мгновенно фотографирует задачу; правая завершает текущую сессию.

Это решение не выдаёт смысловую эвристику за биометрию. Настоящее разделение по говорящим на рынке существует: Yandex SpeechKit размечает до двух спикеров, а OpenAI предлагает отдельную транскрипционную модель с diarization. Оптимальная архитектура для QuickCue — гибридная: показывать быстрый текст Apple Speech сразу, затем отправлять короткие перекрывающиеся аудиофрагменты выбранному сервису и через несколько секунд уточнять роли. В версии 0.3 отправка аудио ещё не включена, потому что она требует отдельного согласия, тарифа и добавляет задержку.

Заданные по умолчанию model IDs — лишь стартовые конфигурации на дату подготовки проекта. Перед live-запросом проверьте доступность в своём аккаунте:

- OpenAI: `gpt-5.4-mini`, Responses API.
- DeepSeek: `deepseek-v4-flash`, Chat Completions, thinking disabled ради скорости.
- Claude: `claude-sonnet-5`, Messages API, adaptive thinking disabled в fast path.
- xAI: `grok-4.6`, Chat Completions.
- YandexGPT: `yandexgpt-5-pro/latest` через OpenAI-совместимый Chat Completions API Yandex AI Studio.

Ни один ключ не включён. Фраза «подключаемые клиенты» означает, что транспорт, payload и SSE parsing реализованы, но валидность каждого аккаунта/model ID всё равно проверяется интеграционным smoke test на устройстве.

## Приоритет скорости

Цели из ТЗ:

| Этап | Цель |
|---|---:|
| Пауза/конец фразы | 300–650 мс |
| Локальное определение вопроса | до 50 мс |
| Первый фрагмент AI | желательно 1–1,5 с, допустимо до 2,5 с |
| Короткий полный ответ | желательно 3–4 с |

Время измеряется монотонными часами и пишется в `AnswerRecord` плюс unified logging category `latency`. Резервный запрос по умолчанию стартует через 1,7 с. Ответ ограничен 220 output tokens и системной инструкцией на 3–5 тезисов. DeepSeek и Claude thinking выключены в fast path.

Цели не являются гарантией: сеть, очередь провайдера, модель, prompt cache и размер изображения влияют на задержку. Автовыбор по p50/p95 оставлен следующим этапом после 50–100 реальных примеров.

## Лимиты и расходы

Искусственного жёсткого paywall нет. MVP использует три слоя:

1. Защита от ошибок: дедупликация 8 секунд, максимум 2 параллельных запроса, 30-секундный HTTP timeout.
2. Мягкие сессионные предупреждения: 150 вопросов, 30 фото; работа после предупреждения продолжается.
3. Бюджет: 2 000 ₽/месяц, предупреждения на 70%, 90% и 100%.

Каждый поток сохраняет токены, вид запроса и провайдера. Стоимость вычисляется как `inputTokens / 1M × inputRate + outputTokens / 1M × outputRate`. Из-за курсов валют, разных cache rates, image pricing и меняющихся тарифов значения вводятся вручную и считаются **оценкой**, а не банковской сверкой.

## Проверки на macOS

```bash
xcodegen generate
xcodebuild \
  -project QuickCue.xcodeproj \
  -scheme QuickCue \
  -destination 'platform=iOS Simulator,name=iPhone 15 Pro Max' \
  test
```

## Следующий безопасный этап

1. Скомпилировать и прогнать unit tests в актуальном Xcode.
2. На физическом iPhone измерить Speech pause → TTFT на 20 mock-вопросах.
3. Подключать по одному провайдеру и делать 5 текстовых + 2 фото smoke tests.
4. Зафиксировать реальные model IDs, p50/p95, ошибки и тарифы.
5. До внешнего TestFlight вынести ключи на backend и добавить отмену проигравшего fallback-запроса.
