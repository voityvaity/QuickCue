# Xcode и TestFlight

## Обновление уже установленного приложения

QuickCue уже установлен пользователем через Sideloadly; Developer Mode и доверие профилю уже включены. Повторять эти действия без нового системного запроса не требуется.

Для 0.3.1 сначала дождитесь успешной сборки нужного commit в GitHub Actions и скачайте её `QuickCue-unsigned.ipa`. Сам файл unsigned IPA не является подписанной TestFlight-сборкой. Подпишите его прежним способом и установите поверх существующего QuickCue с тем же Bundle Identifier, Apple ID/подписывающей командой и совместимыми Keychain access groups. Не удаляйте старое приложение ради обновления: удаление может уничтожить локальную историю и фотографии.

Перед обновлением сохраните резервную копию iPhone и, по возможности, экспорт истории. После установки проверьте старые сессии, реплики, ответы, фотографии и доступность сохранённых ключей. Смена Bundle Identifier или команды подписи может создать другое приложение либо сделать прежний Keychain недоступным; сохранность при такой смене не обещается. При экране ошибки базы используйте «Повторить открытие», сохраните текст/скриншот ошибки и не переустанавливайте приложение с удалением данных.

При бесплатной подписи срок профиля ограничен: переподпись через Sideloadly остаётся частью текущего персонального способа установки. TestFlight — отдельный путь с Apple Developer/App Store Connect, не замена файла IPA без подписания.

## Локальный запуск на iPhone 15 Pro Max

1. На macOS установите Xcode 26 или новее с iOS 26 SDK и XcodeGen.
2. В корне проекта выполните `xcodegen generate`.
3. Откройте `QuickCue.xcodeproj`.
4. В target `QuickCue` → Signing & Capabilities выберите свою Apple Developer Team. При обновлении существующей установки сохраняйте её Bundle Identifier и совместимую подпись; новый идентификатор используйте только для намеренно отдельной тестовой установки.
5. Подключите iPhone 15 Pro Max, подтвердите Developer Mode и выберите устройство как run destination.
6. Первый запуск оставьте в Mock. Разрешите микрофон, Speech Recognition, камеру и Bluetooth только при запросе соответствующей функции.
7. Проверьте ручной вопрос, потоковую карточку, историю и фотографию до включения реального провайдера. Отдельно проверьте Stop/background, смену сессии во время ответа и сохранность истории после обновления.
8. Выполните XCTest, включая реальную миграцию исходной неверсионированной базы. Успех создания новой пустой базы не заменяет проверку обновления.

## Архив и TestFlight

1. Установите уникальные `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION` в `project.yml`, снова выполните `xcodegen generate`.
2. В Xcode выберите `Any iOS Device (arm64)` и `Product → Archive`.
3. В Organizer выполните `Distribute App → App Store Connect → Upload`.
4. Подготовьте публичную privacy policy, support URL и App Privacy ответы по фактическим потокам данных: Apple Speech, AI-провайдеры/шлюзы, текст, фото и возможные серверные логи. Используйте release checklist в `PRIVACY.md`; пустой список collected data в локальном manifest не заменяет эту проверку.
5. Не встраивайте личный или общий коммерческий provider key в сборку. Допустимый технический вариант — BYOK, где каждый тестировщик вводит собственный ключ; другой вариант — backend с серверными секретами, авторизацией и ограничением расходов. BYOK не освобождает от требований приватности, условий AI-сервиса и App Review.
6. Добавьте сборку во внутреннюю группу TestFlight, затем отдельно отправляйте на Beta App Review при внешнем тестировании.

Перед загрузкой выполните tests/build на macOS, App Store validation и реальный smoke test на iPhone, включая чистую установку и обновление поверх старой. Проверьте наличие `PrivacyInfo.xcprivacy` в готовом `.app`, а не только в исходниках.

Для текущей работы выполненная на Windows статическая проверка не подтверждает Xcode-компиляцию, code signing, результаты migration XCTest и разрешения на устройстве. GitHub Actions может выполнить simulator tests и создать unsigned IPA, но не проверяет физический микрофон, камеру, Sideloadly или TestFlight. Факт готовности TestFlight отмечается только после реальной подписанной загрузки и обработки сборки в App Store Connect.

Gate релиза: сначала проверить 0.3.1 на физическом iPhone 15 Pro Max. Затем переходить к большим изменениям 0.4–0.6; не объединять первую миграцию пользовательской истории с непроверенной сменой распознавателя или облачной диаризацией.
