# QuickCue 0.3.1 — проверка перед следующим этапом

## Границы релиза

Build 7 включает код этапов 01–14, сохраняя пять вкладок и оформление. Это не заявление о завершении всей дорожной карты: итоговый CI, миграция на реальном устройстве, качество камеры/речи, LAN-доставка и конкретные аппаратные кнопки ещё требуют проверки на iPhone. SpeechAnalyzer и сетевой адаптер диаризации не включены без сравнительных измерений и отдельной privacy-проверки. Новая пятираздельная навигация остаётся preview и не заменяет текущие вкладки без отдельного одобрения пользователя.

Ключи не создавались и не встраивались. После c55294f HTTP-проверки адаптеров используют детерминированный `streamFactory`, а не URLProtocol. В локальном пакете A они дополнены общим production `SSEDecoder` и отдельными Darwin URLSession/loopback-тестами. Последние пока не запускались: [статус пакета A](PACKAGE-A-REVIEW.md). Ни одна автоматическая проверка не обращается к платному API. Реальные model IDs, billing и права доступа проверяет пользователь своим ключом.

## Основные контракты

- `RequestScheduler` принимает только задачи активной сессии, максимум две одновременно, и выдаёт awaitable ticket. Фото, речь, ручной ввод и вариации используют один путь. Отмена завершает ticket и фиксирует `cancelled`.
- `SessionStore` запрещает публикацию после End/background, сохраняет session ID через асинхронную подготовку фото, обновляет context по ID исправленной реплики и не возобновляет микрофон автоматически после background.
- SessionStore и интерфейс истории используют один main ModelContext: удалённая сессия не получает поздние расходы от отменённого запроса.
- `SpeechLifecycle` защищает разрешения/запуск/restart generation-токеном. Partial-строка не считается вопросом до final. Паузы 500/900/1300 мс лишь запрашивают final; ожидание final может добавить задержку и требует реального измерения.
- `LatencyFallbackRouter` выбирает первый непустой текст, отменяет проигравшего, сообщает каждую фактически начатую попытку в `UsageLedger`. Обрыв после первых слов — ошибка с сохранённым частичным ответом, не успешное завершение.
- `ProviderConnectionChecker` проверяет весь stream с таймаутом 15 с. Верификация относится к конкретной конфигурации; её изменение во время теста не может пометить новый адрес/ключ проверенным.
- При постановке запроса в очередь фиксируются endpoint, модель, ключ и промпт. Новый ключ из редактора не попадёт на старый адрес ожидающего запроса. Тарифы пока читаются при завершении попытки; менять их во время запроса не рекомендуется.
- HTTP/SSE ошибки классифицируются без сохранения upstream error body. [OpenAI streaming events](https://developers.openai.com/api/docs/guides/streaming-responses) обрабатываются отдельно: delta, completed, incomplete и failed.
- Фото API ограничено 1600 px по длинной стороне и 1,5 МБ; исходный JPEG хранится отдельно. Быстрый снимок сначала показывает OCR, получателя и подтверждение; vision-запрос не может незаметно проиграть OCR-only резерву.
- «Эфир», «Диалог» и «Код/фото» имеют отдельные стили/инструкции. Точный снимок промпта, версия и тип сценария сохраняются с ответом; прежний общий пользовательский промпт сохраняется до явного перехода.
- SwiftData V1–V7 мигрируется последовательно без автоматического reset. V6 добавляет speech/queue timing, V7 — источник и приоритет роли. Отдельный test-only framework создаёт исходную unversioned базу, а fixture-тесты открывают прежние URL новой схемой.
- Камера принимает system capture event только на активном экране; Action Button-команда лишь открывает камеру. GATT BLE включается явно и требует UUID конкретного пульта.
- Роли имеют быстрый и ручной режим. Экспериментальный A/B-каркас не отправляет аудио: сетевой получатель не подключён, buffer bounded/in-memory и очищается при Stop/background/end.
- Диагностический журнал принимает только типизированные технические события, ограничен 10 МБ/7 днями и не содержит разговоры, OCR, фото, аудио, prompt, URL или ключи. Ручной архив состоит из трёх фиксированных файлов с checksums и проверяется строгим офлайн-анализатором.
- Привязка Windows Receiver и автодоставка — разные действия. До opt-in нет диагностической сети; затем архив шифруется для одного указанного LAN-приёмника, очередь ограничена тремя элементами, offline не блокирует приложение, revoke удаляет credential iPhone. Обратных команд нет.
- Preflight читает локальные разрешения и сохранённое состояние проверки AI без автоматического запроса. План подготовки создаётся только по кнопке через общий request gate, сохраняется редактируемым и учитывается без фиктивной беседы.

## Что проверяется автоматически

- Структура PrivacyInfo.xcprivacy, версия релиза и поиск вероятных секретов без вывода значений.
- Синтаксис Swift можно дополнительно проверить локальным parser; это не typecheck и не XCTest.
- Xcode CI: Debug Simulator build, XCTest, сохранение `.xcresult`, Release iphoneos build и unsigned IPA.
- Статическая тестовая библиотека старых моделей использует [XcodeGen framework.static](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md) и `embed: false`; она не является зависимостью production-приложения.
- Тесты: scheduler cancel/end/reentrancy и общий gate подготовки; старый photo/OCR callback; camera phase/debounce/route; lifecycle partial/final и раздельные speech timing; corpus 30+20; ручная роль, ambiguous/stale A/B и очистка буфера; fallback; usage; SSE/API; key OCR; timeline; migrations V1–V7 и recovery; diagnostics allowlist/retention/archive; encrypted pair/delivery/offline/revoke; локальный preflight и сохранение планов.

## Проверка на iPhone 15 Pro Max

Установить IPA **поверх** прежней сборки с прежним bundle ID и способом подписи. Не удалять старое приложение: удаление может стереть локальную историю. Сначала убедиться, что старые реплики, ответы, фото и ключи доступны.

1. Mock включён: вручную задать три вопроса подряд; увидеть очередь, отменить один; ответы остальных не теряются.
2. Задать вопросы и сразу завершить сессию. Начать новую: ни один старый вопрос/ответ не появляется в ней.
3. Начать выдачу разрешения на микрофон и уйти с вкладки. После разрешения микрофон сам не включается.
4. Произнести «Как работает… декоратор в Python?» с паузой. В истории должен быть один завершённый вопрос, без частичной копии.
5. Переключить вкладку в середине фразы; незавершённая фраза не отправляется. Уйти на домашний экран/заблокировать iPhone: микрофон и запросы остановлены. Вернуться: ручной ввод и новый запуск снова доступны.
6. В «Диалоге» изменить «Вы / Собеседник» и отправить следующий вопрос о контексте. Проверить полный диалог в истории и экспорте.
7. Сделать 10 быстрых фото и несколько через отдельную камеру. Ответ виден на том же экране; Stop/End/background во время камеры/OCR не создаёт новую сессию и не отправляет поздний запрос.
8. В настройках новый ключ без теста — оранжевый, не зелёный. После полного успешного теста — зелёный с датой/моделью. Изменить ключ/Folder ID/URL/модель: проверка сброшена.
9. Ввести неверный ключ, model ID, отключить сеть: понятная ошибка без содержимого запроса. Для Yandex дополнительно проверить billing и права сервисного аккаунта.
10. Проверить 5 streaming-вопросов к Yandex и одному собственному шлюзу. Фото — 2 vision-запроса или явно обозначенный OCR-only путь. Эти проверки платные и запускаются пользователем.
11. В `Настройки → Локальная диагностика` подготовить ручной экспорт. На ПК запустить офлайн-анализатор: видны build/категории/latency, но поиск контрольных фраз из разговора, вакансии, OCR и ключа в архиве ничего не находит.
12. До включения автодоставки убедиться, что сессия не появляется в Inbox ПК. Затем привязать receiver, отдельно включить toggle, завершить сессию и увидеть один валидный архив. Выключить receiver: QuickCue остаётся отзывчивым и показывает один ожидающий отчёт; отзыв пары прекращает отправку.
13. Открыть preflight без сети: denied/stale не зелёные, а сетевого теста нет до отдельного нажатия. Создать Mock-план для одной вакансии, отредактировать его, перезапустить приложение и проверить сохранение; в истории «Эфира» фиктивная сессия не появляется.
14. Открыть preview будущей навигации и проверить все пять пунктов. Основные вкладки приложения при этом должны остаться прежними; «Практика» честно помечена будущей функцией.

## Измеримые цели, пока не подтверждённые устройством

- Ноль повторных запросов/смешивания сессий; после Stop микрофон не работает.
- Текстовый corpus детектора: precision и recall ≥90%; это не тест точности распознавания аудио.
- На стабильном Wi-Fi: TTFT p50 ≤1,5 с, p95 ≤2,5 с; короткий ответ p50 ≤4 с. Показатели модели, сети и финализации речи измеряются отдельно.
- Минимум 9 из 10 фото пригодны для OCR либо есть понятный путь пересъёмки.

После этой проверки можно начинать только этап 15 по отдельному сообщению пользователя. TestFlight не считается готовым по наличию unsigned IPA: нужны подписанный archive, App Store validation, privacy policy/App Privacy и проверка установки/обновления.
