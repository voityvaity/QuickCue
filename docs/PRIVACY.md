# Конфиденциальность и безопасное использование

- Сессия начинается только после нажатия «Начать слушать»; активный микрофон заметен в интерфейсе и системным индикатором iOS.
- Приложение предназначено для окружающей речи рядом с телефоном и не пытается получать аудио звонков или других приложений.
- Перед записью других людей пользователь обязан получить согласие в соответствии с применимым правом и правилами места использования.
- QuickCue не сохраняет аудиофайлы. Расшифровки, ответы и оригиналы фотографий хранятся в sandbox приложения; системные резервные копии iPhone имеют отдельный жизненный цикл. Удаление локальной истории не отзывает уже переданные провайдерам копии.
- Apple Speech может обрабатывать аудио через сеть: текущий `SFSpeechRecognizer` не принуждён к режиму on-device. «Аудио не сохраняется приложением» не означает «аудио никогда не покидает iPhone».
- При выборе удалённого провайдера вопрос, контекст и иногда фотография покидают устройство и обрабатываются по условиям выбранного сервиса.
- Профили кандидата, вакансии и извлечённый текст материалов хранятся локально. Импорт TXT/PDF/фото OCR сам по себе не вызывает сеть; при начале сессии выбранные данные превращаются в ограниченный снимок, который затем передаётся выбранному AI вместе с вопросами. Исходный импортированный файл QuickCue не копирует: он остаётся в Files/Фото и их резервных копиях.
- Пользовательский API-шлюз является дополнительным посредником: он может видеть запросы, хранить собственные логи и перенаправлять данные другим моделям. QuickCue показывает предупреждение, но не может проверить политику стороннего сервиса.
- Keychain защищает индивидуальный ключ на устройстве, но не делает встраивание общего коммерческого ключа безопасным. Для распространяемой сборки допустим технический путь BYOK — каждый пользователь вводит собственный ключ — либо backend, хранящий секреты на сервере. Ни один вариант не является автоматической гарантией соответствия правилам публикации.
- Фото API-ключа распознаётся локально через Apple Vision, не добавляется в историю QuickCue и не отправляется AI-провайдеру. Распознанную строку нужно проверить перед сохранением из-за похожих символов. Выбранный исходник в медиатеке, её синхронизации и резервных копиях приложение не удаляет. Временное раскрытие ключа на экране доступно для проверки — не делайте скриншот с открытым секретом.
- Скриншот с видимым или частично скрытым API-ключом следует считать утечкой: такой ключ нужно отозвать у провайдера и создать заново.
- QuickCue не предназначен для скрытого использования, обхода прокторинга, контроля работодателя или правил собеседования/экзамена.

## Прозрачность 0.3.1

Перед фото-запросом интерфейс показывает, кто получит изображение и текст или только OCR, включая возможный резервный сервис. Для API создаётся уменьшенная копия, оригинал остаётся локальным. Запуск fallback может передать один запрос двум разным сервисам; отмена проигравшей попытки не гарантирует удаления уже принятых данных у сервиса и отсутствия оплаты.

Проверка соединения тоже обращается к выбранному провайдеру и может расходовать токены. `store: false` в OpenAI-запросе не следует трактовать как проверенную гарантию отсутствия любых серверных журналов или иных сроков хранения. Политику нужно проверять для каждого реально используемого сервиса и режима аккаунта.

Логи QuickCue ограничены request ID, провайдером, задержкой и безопасным кодом ошибки. Приложение не добавляет в эти логи API-ключи, реплики и тела ошибок шлюза. Экспорт истории, содержимое интерфейса и пользовательские скриншоты при этом могут содержать личные данные.

Экспериментальная диаризация имеет отдельный выключенный по умолчанию consent. В build 6 сетевой обработчик не подключён: короткий bounded-буфер существует только в памяти и очищается при Stop, background и завершении сессии. Поэтому даже включённый consent сейчас не вызывает внешнюю отправку. Любой будущий получатель должен быть показан отдельно; согласие на Apple Speech его не заменяет.

## App Privacy: черновой release checklist

Это список проверки перед публикацией, не юридическое заключение и не готовая декларация соответствия. Здесь намеренно не утверждается, что приложение «ничего не собирает».

- [ ] Проверить итоговый `PrivacyInfo.xcprivacy` внутри подписанного `.app`. В исходнике объявлен доступ к UserDefaults с причиной `CA92.1`; нужно проверить все required-reason APIs приложения и его зависимостей в итоговой сборке.
- [ ] Не использовать пустой `NSPrivacyCollectedDataTypes` как доказательство «нет сбора». Manifest не описывает автоматически фактическую обработку на Apple Speech, AI API, шлюзе или будущем backend и не заменяет ответы App Privacy в App Store Connect.
- [ ] Составить инвентаризацию реальных данных: аудио для Speech, распознанные/введённые вопросы, контекст, фото/OCR, промпты, ключ авторизации, сетевые метаданные и диагностика. Отдельно указать, что остаётся только на устройстве, что покидает его и какой стороной обрабатывается.
- [ ] Оценить Apple Speech в реально используемом режиме: локальная доступность, возможная сетевая обработка, назначение и применимые условия. Не обещать локальное распознавание без проверки и принудительного on-device режима.
- [ ] Для каждого встроенного API и поддерживаемого шлюза уточнить получателей/субподрядчиков, цели обработки, хранение журналов, использование для обучения, удаление и настройки аккаунта. Не переносить политику одного провайдера на остальные; неизвестный пользовательский URL не считать доверенным по умолчанию.
- [ ] На основании этой инвентаризации решить, какие категории декларировать в App Store Connect, связаны ли они с пользователем и используются ли для tracking. Категории аудио, фото, пользовательского содержимого и диагностики требуют оценки по фактическому поведению, а не отметки по предположению.
- [ ] Опубликовать privacy policy и контакт поддержки; описать BYOK/шлюзы, локальную историю, системные резервные копии, экспорт/удаление и пределы удаления уже переданных копий. Проверить соответствие текста реальной сборке.
- [ ] Проверить разрешения, заметность активного микрофона, остановку при background/Stop и отсутствие нежелательной передачи в Mock. Проверить обновление без удаления истории на физическом iPhone.
- [ ] При добавлении SDK, аналитики, backend, синхронизации или облачной диаризации повторить аудит и обновить manifest, policy и App Privacy ответы до публикации.

Статическая проверка manifest на Windows подтверждает только структуру и выбранные декларации. Она не доказывает App Review/TestFlight readiness, отсутствие серверного хранения или корректность всех privacy answers.
